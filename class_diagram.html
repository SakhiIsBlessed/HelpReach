📋 Class Diagram Explanation

👤 User Class
Attributes: ID, name, email, phone, location, password_hash, role, created_at
Methods: register(), login(), updateProfile(), getProfile(), logout()
Purpose: Represents regular users/donors on the platform
🏢 NGO Class
Attributes: ID, name, email, phone, address, registration_number, mission_statement
Methods: register(), login(), uploadDocuments(), claimDonation(), viewReceivedDonations()
Purpose: Represents organizations that receive donations
🎁 Donation Class
Attributes: ID, donor_id, ngo_id, description, status, created_at, updated_at
Methods: createDonation(), updateStatus(), claimDonation(), completeDonation()
Purpose: Core class representing a donation containing items and photos
Status: pending, claimed, approved, rejected, completed
📦 DonationItem Class
Attributes: ID, donation_id, item_name, quantity, condition
Methods: addItem(), updateQuantity(), getDetails()
Purpose: Represents individual items within a donation
📸 DonationPhoto Class
Attributes: ID, donation_id, filename, filepath, uploaded_at
Methods: uploadPhoto(), deletePhoto(), getURL()
Purpose: Manages photos/images for donations
📄 NGODocuments Class
Attributes: ID, ngo_id, filename, original_filename, uploaded_at
Methods: uploadDocument(), verify(), reject()
Purpose: Stores verification documents for NGO registration
🏦 NGOBankAccount Class
Attributes: ID, ngo_id, account_holder_name, account_number, bank_name, ifsc_code
Methods: addBankAccount(), updateBankAccount(), validateAccount()
Purpose: Stores banking information for NGOs
✅ DonationClaim Class
Attributes: ID, donation_id, ngo_id, status, claimed_at, updated_at
Methods: createClaim(), approveClaim(), rejectClaim(), getStatus()
Purpose: Represents an NGO's claim to receive a donation
Status: pending, approved, rejected, completed
🔔 PushSubscription Class
Attributes: ID, endpoint, p256dh, auth_key, created_at
Methods: subscribe(), unsubscribe(), sendNotification()
Purpose: Manages browser push notifications for users
📧 EmailLog Class
Attributes: ID, recipient_email, subject, email_type, sent_at
Methods: logEmail(), sendEmail(), getHistory()
Purpose: Tracks all emails sent by the system for auditing
🔐 Authentication Class
Methods: loginUser(), registerUser(), validatePassword(), generateToken(), verifyToken()
Purpose: Handles all authentication & security operations
🔔 NotificationService Class
Methods: sendEmail(), sendPushNotification(), notifyDonor(), notifyNGO(), getTemplate()
Purpose: Manages all notifications (email & push)
📊 Relationship Types in Diagram:
Relationship Notation Example
One-to-Many 1 --|> * One User creates many Donations
One-to-One 1 -- 1 One DonationClaim claimed by one NGO
Composition --> Donation contains DonationItems
Aggregation -- Authentication validates User
✨ Key Design Patterns:
Encapsulation: Each class has private attributes and public methods
Inheritance: User and NGO could inherit from a common Person/Account class
Composition: Donation is composed of DonationItems and DonationPhotos
Association: User creates Donation; NGO receives DonationClaim
Services: Authentication & NotificationService provide utility functions
